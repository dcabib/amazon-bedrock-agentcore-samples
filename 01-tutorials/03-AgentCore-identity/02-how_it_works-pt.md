# Como o Bedrock AgentCore Identity funciona

## Introdução

AgentCore Identity aborda um desafio fundamental na implantação de agentes de IA: permitir que agentes acessem com segurança dados específicos do usuário em múltiplos serviços sem comprometer a segurança ou a experiência do usuário. Abordagens tradicionais ou usam credenciais de acesso amplas sem controles granulares ou exigem consentimento explícito do usuário para cada integração de serviço (criando uma experiência ruim para o usuário). AgentCore Identity resolve isso através de um fluxo de trabalho abrangente que implementa princípios de segurança zero trust e autenticação baseada em delegação.

O serviço opera no princípio de delegação em vez de representação. Em vez de agentes usarem credenciais de usuário diretamente, os agentes se autenticam como eles mesmos enquanto carregam contexto verificável do usuário. Esta abordagem habilita controle de acesso granular, trilhas de auditoria abrangentes e a capacidade de revogar acesso do agente independentemente do acesso do usuário. O fluxo de trabalho orquestra autenticação e autorização complexas em múltiplos domínios de confiança enquanto apresenta uma interface simples para desenvolvedores.

Em seu núcleo, AgentCore Identity fornece mecanismos de autenticação seguros para agentes acessarem recursos mantendo limites de segurança apropriados. Isso habilita serviços a tomar decisões de autorização apropriadas, suportando casos de uso sofisticados como agentes cross-service que podem acessar sistemas internos de calendário e serviços externos como Google Calendar dentro de um único fluxo de trabalho.

O fluxo de trabalho do AgentCore Identity consiste nas seguintes etapas:

**Usuário faz login com OAuth/OIDC e passa token para aplicação** — O usuário se autentica através do provedor de identidade existente de sua organização (como Auth0, Cognito ou outros sistemas compatíveis com OIDC) e recebe um token de acesso ou token de identidade. Este token contém as informações de identidade do usuário e escopos autorizados, estabelecendo o contexto de identidade do usuário para todo o fluxo de trabalho. A aplicação recebe este token e o usará para autorizar requisições ao agente. 

**Aplicação voltada ao usuário processa login do usuário** — A aplicação valida o token de autenticação do usuário e estabelece uma sessão segura. Esta etapa garante que o usuário esteja propriamente autenticado e autorizado a acessar as funcionalidades da aplicação, incluindo a capacidade de invocar agentes de IA. A aplicação também pode extrair informações de identidade do usuário do token para fins de personalização e controle de acesso.

**Usuário solicita acesso a recurso por agente de IA** — Quando o usuário inicia uma interação com o agente, a aplicação faz uma requisição para invocar o agente de IA em nome do usuário. Esta requisição inclui o token de autenticação do usuário e qualquer contexto necessário sobre o que o agente precisa realizar. A aplicação atua como um proxy, encaminhando a requisição autenticada do usuário para a infraestrutura do agente enquanto mantém o contexto de identidade do usuário.

**Aplicação voltada ao usuário faz requisição ao serviço de agente com token de usuário** — O serviço Bedrock AgentCore recebe a requisição e valida o token do usuário contra políticas de autorização configuradas. Esta validação inclui verificar a assinatura do token, expiração, emissor, audiência e escopos requeridos. O serviço garante que o usuário tem as permissões necessárias para invocar o agente específico e que a requisição atende todos os requisitos de segurança antes de prosseguir.

**Bedrock AgentCore solicita token de acesso de carga de trabalho do Agent Credential Provider** — O serviço de agente inicia um processo de troca de token para obter um token de acesso de carga de trabalho (tecnicamente um workload access token). O serviço de agente submete o token do usuário para a API de troca de tokens do AgentCore Identity. A requisição é autorizada com credenciais IAM. Isso habilita acesso seguro e auditável a recursos downstream enquanto mantém a cadeia de confiança e suporta decisões de autorização. 

**AgentCore Identity valida o token do usuário e emite um token de acesso de carga de trabalho** — AgentCore Identity valida a assinatura, expiração, emissor, audiência e escopos do token do usuário. Em seguida, retorna um token de acesso de carga de trabalho. Isso habilita acesso seguro e auditável a recursos downstream enquanto mantém a cadeia de confiança. O AgentCore Identity executa validação zero trust abrangente da requisição, incluindo verificar a identidade do agente, validar a assinatura e reivindicações do token OAuth/OIDC original do usuário, e verificar se o agente tem permissão para acessar os recursos solicitados em nome do usuário. Esta validação ocorre independentemente da origem ou relacionamentos de confiança anteriores, garantindo que cada requisição seja autenticada e autorizada independentemente. 

**Aplicação de agente de IA invoca agente** — A aplicação do agente recebe o token de acesso de carga de trabalho e começa a executar a tarefa solicitada. O agente agora pode operar com uma prova verificável de sua própria identidade e do usuário em cujo nome está atuando. Isso habilita o agente a fazer requisições autenticadas a várias ferramentas e recursos mantendo rastreabilidade completa das ações de volta ao usuário original.

**Agente solicita token de acesso a recurso** — Quando o agente precisa acessar recursos AWS e serviços de terceiros (como Google Calendar, Slack ou APIs internas), ele solicita credenciais apropriadas do AgentCore Credential Provider. O agente apresenta seu token de acesso de carga de trabalho como prova de sua identidade e autorização. O sistema valida este token e determina quais recursos o agente tem permissão para acessar com base em políticas configuradas e consentimento do usuário. AgentCore Identity pode ter um token existente para a identidade de usuário e recurso solicitados, caso em que retorna o token de acesso ao recurso. 

**Amazon Bedrock AgentCore Identity solicita autenticação do usuário com recurso** — Se AgentCore Identity não tem um token de acesso existente para o recurso solicitado no cofre de tokens, ele retorna uma resposta indicando que o consentimento do usuário é necessário na URL fornecida. Para recursos que requerem consentimento explícito do usuário (como serviços de terceiros como Google Calendar), o sistema pode precisar iniciar um fluxo de autenticação do usuário. Isso tipicamente envolve redirecionar o usuário para o servidor de autorização do provedor de recursos (como endpoints OAuth 2.0 do Google ou Azure AD da Microsoft) para conceder permissão para o agente acessar seus dados. Esta etapa garante que os usuários mantenham controle sobre quais recursos os agentes podem acessar em seu nome e suporta tanto fluxos OAuth 2.0 client credentials grant (máquina-para-máquina) quanto OAuth 2.0 authorization code grant (acesso delegado pelo usuário). 

**Bedrock AgentCore solicita autenticação do usuário** — O serviço de agente retorna uma resposta para a aplicação voltada ao usuário, passando a URL de autorização solicitada.

**Aplicação voltada ao usuário exibe prompt de autenticação e consentimento** — O usuário é solicitado a inserir suas credenciais e compartilhar seus dados com o agente.

**Usuário consente em compartilhar dados** — O usuário aceita o prompt de consentimento do provedor de terceiros.

**Recurso de terceiros valida credenciais do usuário e emite token de acesso ao recurso** — O provedor de serviço de terceiros (como Google, Microsoft ou Salesforce) valida as credenciais e consentimento do usuário, então emite um token de acesso especificamente para o agente usar. Este token é tipicamente com escopo apenas para as permissões que o usuário explicitamente concedeu ao agente, seguindo o princípio de acesso com privilégio mínimo. A URL de callback desta requisição de autorização é um endpoint de serviço AgentCore Identity que processa a resposta do provedor e coleta o token de acesso para o recurso solicitado.

**AgentCore Identity armazena e retorna token de acesso ao recurso** — O AgentCore Identity retorna o token de acesso ao recurso em resposta à requisição do agente. O serviço também armazena com segurança o token de acesso ao recurso no cofre de tokens para uso futuro, associando-o com a combinação específica de identidade de agente e identidade de usuário. Isso habilita requisições subsequentes a reutilizar o token sem exigir autenticação repetida do usuário, melhorando a experiência do usuário enquanto mantém segurança. O token é criptografado e com controle de acesso para prevenir recuperação não autorizada. O cofre de tokens opera sob princípios zero trust, garantindo que credenciais só podem ser acessadas pela exata combinação de agente e usuário que originalmente as obteve. Isso previne acesso cruzado não autorizado entre diferentes agentes ou usuários. 

**Agente solicita dados do recurso.** — Usando o token de acesso específico do recurso, o agente faz chamadas de API para ler ou escrever dados do recurso de terceiros. O agente opera dentro dos limites das permissões concedidas pelo usuário e das capacidades definidas pela API do provedor de recurso. Todas as ações são realizadas com a identidade do agente claramente estabelecida para fins de auditoria e segurança.

**Recurso de terceiros valida token de acesso ao recurso e retorna dados** — O serviço de terceiros valida o token de acesso fornecido pelo agente, garantindo que é válido, não expirado e tem os escopos necessários para a operação solicitada. Após validação bem-sucedida, o recurso retorna os dados solicitados ou confirma a conclusão da ação solicitada. Esta validação garante que apenas agentes autorizados com consentimento apropriado do usuário possam acessar recursos protegidos.

**Aplicação de agente de IA monta resposta** — O agente processa os dados recebidos de recursos AWS e serviços de terceiros e combina com qualquer lógica e contexto adicional para criar uma resposta abrangente. O agente mantém contexto sobre a requisição original do usuário e garante que a resposta atenda as necessidades do usuário enquanto incorpora dados dos recursos acessados.

**AgentCore retorna resposta para aplicação** — O agente envia sua resposta completa de volta para a aplicação voltada ao usuário. Esta resposta inclui os resultados das ações do agente, quaisquer dados recuperados de recursos AWS e serviços de terceiros, e confirmação de tarefas completadas. A resposta mantém o contexto de segurança e fornece informações de auditoria sobre quais ações foram realizadas em nome do usuário.

**Aplicação voltada ao usuário exibe resposta** — A aplicação apresenta a resposta do agente ao usuário em um formato apropriado, seja texto, dados estruturados ou confirmação de ações completadas. O usuário pode ver os resultados de sua requisição e entender o que o agente realizou usando seu acesso autorizado a vários recursos.

**Processo completa (Concluído)** — O fluxo de trabalho conclui com todos os tokens propriamente gerenciados, logs de auditoria registrados e a requisição do usuário cumprida. O sistema mantém segurança durante todo o processo enquanto fornece uma experiência contínua para usuários que querem aproveitar agentes de IA para acessar e manipular seus dados em múltiplos serviços e plataformas.

Este fluxo de trabalho é construído sobre vários princípios técnicos chave que distinguem o AgentCore Credential Provider de abordagens tradicionais de autenticação. O serviço implementa segurança zero trust, onde cada requisição é validada independentemente da origem ou relacionamentos de confiança anteriores. Ele usa autenticação baseada em delegação em vez de representação, garantindo que agentes sempre se autentiquem como eles mesmos enquanto carregam contexto do usuário. O serviço é compatível com MCP (Model Context Protocol), suportando protocolos padrão para comunicação agente-ferramenta. Finalmente, ele fornece suporte multiplataforma, permitindo que agentes operem na AWS, outros provedores de nuvem e ambientes on-premise enquanto mantêm padrões de segurança consistentes.
